前言

在 MDN 的 JavaScript 系列中我們已經學習了 callback、promise、generator、async/await。而在這一篇文章中，作者將以實際樣例闡述非同步發展歷史，介紹每種實現方式的優勢與不足，以期幫助讀者熟悉歷史程序並把握非同步發展的脈絡。

非同步

幾十年前的導航網站，清爽又簡單，沒有什麼特別的功能，只是單純的展示，現成的網頁在伺服器上靜靜躺著，高效毫無壓力，讓人很喜歡。

幾十年後的今天，靜態頁面遠不能滿足使用者的需求，網站變得複雜起來，使用者互動越來越頻繁，從而產生大量複雜的內部互動，為了解決這種複雜，出現了各種系統“模式”，從而很容易的在外部獲取資料，並實時展示給使用者。

獲取外部資料實際上就是“網路呼叫”，這個時候“非同步”這個詞彙出現了。

非同步指兩個或兩個以上的物件或事件不同時存在或發生（或多個相關事物的發生無需等待其前一事物的完成）

非同步 callbacks

非同步 callbacks其實就是函式，只不過是作為引數傳遞給那些在後臺執行的其他函式。當那些後臺執行的程式碼結束，就呼叫 callbacks 函式，通知你工作已經完成，或者其他有趣的事情發生了。

場景

javascript
 程式碼解讀
複製程式碼
let readFile = (path, callBack) => {
  setTimeout(function () {
    callBack(path)
  }, 1000)
}

readFile('first', function () {
  console.log('first readFile success')
  readFile('second', function () {
    console.log('second readFile success')
    readFile('third', function () {
      console.log('third readFile success')
      readFile('fourth', function () {
        console.log('fourth readFile success')
        readFile('fifth', function () {
          console.log('fifth readFile success')
        })
      })
    })
  })
})

優點：

  • 解決了同步問題（即解決了一個任務時間長時，後面的任務排隊，耗時太久，使程式的執行變慢問題）

缺點：

  • 回撥地獄(多層級巢狀)，會導致邏輯混亂，耦合性高，改動一處就會導致全部變動，巢狀多時，錯誤處理複雜
  • 不能使用 try...catch 來抓取錯誤
  • 不能 return
  • 可讀性差

Promise

一個Promise物件代表一個在這個 promise 被建立出來時不一定已知的值。它讓您能夠把非同步操作最終的成功返回值或者失敗原因和相應的處理程式關聯起來。 這樣使得非同步方法可以像同步方法那樣返回值：非同步方法並不會立即返回最終的值，而是會返回一個 promise，以便在未來某個時候把值交給使用者。

場景

javascript
 程式碼解讀
複製程式碼
let readFile = (path) => {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (!path) {
        reject('error!!!')
      } else {
        console.log(path + ' readFile success')
        resolve()
      }
    }, 1000)
  })
}

readFile('first')
  .then(() => readFile('second'))
  .then(() => readFile('third'))
  .then(() => readFile('fourth'))
  .then(() => readFile('fifth'))

優點：

  • 狀態改變後，就不會再變，任何時候都可以得到這個結果
  • 可以將非同步操作以同步操作的流程表達出來，避免了層層巢狀的回撥函式
  • 一定程度上解決了回撥地獄的可讀性問題

缺點：

  • 無法取消 promise
  • 當處於 pending 狀態時，無法得知目前進展到哪一個階段
  • 程式碼冗餘，有一堆任務時也會使語義不清晰

Generator

Generator函式是 ES6 中提供的一種非同步程式設計解決方案。語法上，首先可以把它理解成，Generator函式是一個狀態機，封裝了多個內部狀態，需要使用next()函式來繼續執行下面的程式碼。

特徵

  • function 與函式名之間帶有(*)
  • 函式體內部使用 yield 表示式，函式執行遇到 yield 就返回

場景

javascript
 程式碼解讀
複製程式碼
var readFile = function (name, ms) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      console.log(name + '讀完了')
      resolve()
    }, ms)
  })
}

var gen = function* () {
  console.log('指定generator')
  yield readFile('first', 1000)
  yield readFile('second', 2000)
  yield readFile('third', 3000)
  yield readFile('forth', 4000)
  yield readFile('fifth', 5000)
  return '完成了'
}
var g = gen()
var result = g.next()
result.value
  .then(() => {
    g.next()
  })
  .then(() => {
    g.next()
  })
  .then(() => {
    g.next()
  })
  .then(() => {
    g.next()
  })

優點：

  • 可以控制函式的執行，可以配合 co 函式庫使用

缺點：

  • 流程管理卻不方便（即何時執行第一階段、何時執行第二階段）

async 和 await

async functions 和 await 關鍵字是最近新增到 JavaScript 語言裡面的。它們是 ECMAScript 2017 JavaScript 版的一部分（參見ECMAScript Next support in Mozilla）。簡單來說，它們是基於 promises 的語法糖，使非同步程式碼更易於編寫和閱讀。透過使用它們，非同步程式碼看起來更像是老式同步程式碼，因此它們非常值得學習。

場景 1

javascript
 程式碼解讀
複製程式碼
var readFile = function (name, ms) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      console.log(name + '讀完了')
      resolve()
    }, ms)
  })
}

async function useAsyncAwait() {
  await readFile('first', 1000)
  await readFile('second', 2000)
  await readFile('third', 3000)
  await readFile('forth', 4000)
  await readFile('fifth', 5000)
  console.log('async檔案閱讀完畢')
}
useAsyncAwait()

優點

  • 內建執行器。意味著不需要像 generator 一樣呼叫 next 函式或 co 模組

  • 更廣的適用性。async 和 await 後面跟的都是 promise 函式，原始資料型別會被轉為 promise

  • 語義更清晰、簡潔

    缺點

  • 大量的 await 程式碼會阻塞（程式並不會等在原地，而是繼續事件迴圈，等到響應後繼續往下走）程式執行，每個 await 都會等待前一個完成

場景 2 場景 1 中的程式碼，其實 second，third 的偽請求其實並不依賴於 first，second 的結果，但它們必須等待前一個的完成才能繼續，而我們想要的是它們同時進行，所以正確的操作應該是這樣的。

javascript
 程式碼解讀
複製程式碼
async function useAsyncAwait() {
  const first = readFile('first', 1000)
  const second = readFile('second', 2000)
  const third = readFile('third', 3000)
  const forth = readFile('forth', 4000)
  const fifth = readFile('fifth', 5000)
  console.log('async檔案閱讀完畢')

  await first
  await second
  await third
  await forth
  await fifth
}
useAsyncAwait()

在這裡，我們將三個 promise 物件儲存在變數中，這樣可以同時啟動它們關聯的程序。

總結

在這篇文章中，我們已經介紹了 JavaScript 非同步發展史中 --- callback、promise、generator、async/await 的使用方式、優點與缺點。

發展史優點缺點
callback解決了同步問題回撥地獄、可讀性差、無法 try / catch 、無法 return
promise一定程度上解決了回撥地獄的可讀性無法取消、任務多時，同樣存在語義不清晰
generator可以控制函式的執行，可以配合 co 函式庫使用流程管理卻不方便（即何時執行第一階段、何時執行第二階段
async/await語義更清晰、簡潔，內建執行器認知不清晰可能會造成大量 await 阻塞（程式並不會等在原地，而是繼續事件迴圈，等到響應後繼續往下走）情況

而在現有的非同步解決方案中，async/await 是使用人數最多的，它帶給我們最大的好處即同步程式碼的風格，語義簡潔、清晰。
