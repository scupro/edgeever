# 影片筆記：儲存網頁已有字幕

使用者在 YouTube 或嗶哩嗶哩的播放頁選擇「儲存影片筆記到 EdgeEver」。外掛讀取當前頁面的影片資訊和平臺已經提供的字幕，儲存標題、作者、來源連結、可用的封面和帶原片時間戳的字幕。已有字幕且工作區配置了可用的聊天模型時，可以生成總結、大綱和要點；失敗不阻止筆記儲存。

支援 YouTube 普通影片及 Shorts、嗶哩嗶哩普通影片及分 P。直播、番劇、課程和其他頁面不建立影片筆記。頁面沒有字幕時，僅儲存來源資訊和「這一集沒有可用字幕」，不啟動語音識別。影片筆記不提供再次提取字幕的選單，也不下載外部平臺的影片或音軌。

## 筆記附件語音識別

使用者可以在已上傳到筆記的音訊或 MP4/WebM 影片附件上主動選擇「轉錄」。工作區配置 OpenAI 相容語音模型和預設模型；筆記附件 API 僅接受筆記 ID 與歸屬該筆記的附件 ID，不接受媒體 URL。實例校驗附件歸屬，並把當前語音模型地址、名稱及憑據交給已登入客戶端；憑據在實例上加密儲存。Web/桌面客戶端經原有資源介面分段讀取附件，在本機提取音軌並按大小或時長切段，由客戶端把每段不超過 24 MB 的音訊直接傳送到使用者配置的 `/audio/transcriptions` 服務。實例只提供原有附件位元組，不提取或轉換音軌，也不轉發模型請求。Web 瀏覽器中的直連要求模型服務支援跨域請求，並會使模型憑據進入當前瀏覽器會話；桌面端由本機主程序直接請求模型服務。識別文字先展示給使用者，可複製或插入當前筆記。外掛可透過 `context.ai.transcribeResource(noteId, resourceId)` 呼叫同一客戶端能力，也可把自己的音影片 `Blob` 交給 `context.ai.transcribeMedia(blob)`；兩種方法都不在返回值中提供模型憑據，也不接受媒體 URL。附件仍受普通上傳上限約束；無法讀取的媒體格式或音軌會明確報錯。

新增服務時可用尚未儲存的地址、模型 ID 和 Token 測試連線；編輯服務時可選擇已新增的模型，並沿用已儲存的 Token 或輸入新 Token 測試。測試從當前客戶端直連模型服務，傳送一段內建短語音並顯示返回的文字；測試不儲存表單，可能產生少量模型費用。瀏覽器跨域限制與真實轉錄相同。

瀏覽器無法建立直連時，客戶端只能報告連線未完成，不能據此判斷 Token、模型或語音介面無效。服務商不允許跨域請求時，應在桌面客戶端測試；不得為透過 Web 測試而改由實例轉發識別請求。
“OpenAI 相容”只說明介面形狀，不能保證服務商提供 `/audio/transcriptions`；桌面端繞開瀏覽器跨域限制後，仍須透過真實短語音請求驗證該介面及所選模型。

## 已撤回的外部媒體抓取方案：技術備忘

以下記錄未上線的外部媒體抓取設計，供以後評估授權場景時參考，**不是當前產品行為或待實現需求**。撤回範圍包括外部音軌抓取、瀏覽器登入狀態複用、yt-dlp 自動安裝與更新、外部影片識別任務和桌面輪詢。上面的筆記附件語音識別是獨立實現。

### 任務與資料邊界

- 原方案把平臺、影片 ID、來源 URL、時長和無字幕佔位文字編碼進筆記正文的隱藏標記。儲存筆記本身不建任務；使用者在筆記列表主動選擇提取時才建任務。
- API 用工作區和筆記 ID 限定任務，記錄正文內容雜湊；剪藏令牌和演示實例不能建立或領取任務。條件更新只允許一個桌面端領取，約 20 分鐘未完成的任務可重新領取，避免永久卡住。
- 桌面端寫回同一條筆記時帶修訂號和內容雜湊。正文被使用者修改時不覆蓋；原佔位仍在則替換，否則追加實錄。失敗保留原筆記，不自動反覆嘗試。

### 本機媒體處理與模型呼叫

- 原方案按平臺白名單驗證 HTTPS 來源，在本機呼叫 yt-dlp 只選最優音軌，不儲存影片；限制已知時長約 30 分鐘、音訊約 24 MiB、下載和識別超時。任務結束後清理臨時音訊。大小和時長限制只減少資源佔用，不構成版權授權。
- yt-dlp 獨立可執行檔案從其釋出頁取得，並核對 SHA-256；桌面端後臺檢查版本。可選的 `--cookies-from-browser` 會複用本機瀏覽器登入狀態，瀏覽器選擇僅存在本機。這會擴大可獲取的媒體範圍，因此不能把「本機執行」等同於獲得平臺或權利人許可。
- 原方案讓已登入桌面端領取語音模型憑據，並把音訊直接傳送到使用者配置的 OpenAI 相容 `/audio/transcriptions` 介面。當前附件轉錄也由客戶端直連模型服務，但只處理已上傳且歸屬當前筆記的附件；不恢復外部媒體抓取或舊任務機制。
- 模型返回分段時間戳時生成可點回原片的實錄；僅返回全文時寫入普通文字。任務失敗記錄錯誤碼，不把 API Token 寫入診斷資訊。

若未來重新考慮，應先明確內容授權、平臺條款、目標市場和識別服務的資料處理方式，再重新設計入口與驗證範圍；不能直接恢復上述抓取鏈路。
